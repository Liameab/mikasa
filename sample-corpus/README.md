# Sample corpus

Mikasa ships an **original** Chinese study corpus for zero-key demos and automated evaluation
(the golden set is generated from it). No API key is required to try the full pipeline:

```bash
mikasa ingest sample-corpus --profile offline
mikasa ask "Why does L2 regularization prevent overfitting?" --profile offline
```

## Contents

| Item | Format | Purpose |
| --- | --- | --- |
| `notes/` (17 files) | Markdown, numbered | A machine-learning course track (linear regression → deep learning → LLM basics) |
| `机器学习学习路线.txt` | Plain text (**GBK encoded**) | A study roadmap (also exercises encoding detection) |
| `AI 学习路线规划.docx` | Word (heading styles + table) | Planning notes with a weekly schedule table |
| `前沿论文研读笔记.pdf` | PDF (multi-page, repeated header) | Paper-reading notes with page metadata |

Together they cover all four loaders (md / txt / docx / pdf) plus heading-based chunking and page
metadata. The notes deliberately **repeat topics across files** (e.g. "overfitting" appears in
several) so that hybrid retrieval and multi-citation answers (`[1][2]`) show up naturally in a demo.

## Why an original corpus

1. **Clean licensing** — no textbook or paper text is reproduced, so the corpus can be published
   and redistributed with the repository;
2. **Controllability** — the golden set's expected answers are determined solely by this corpus:
   whether a question is answerable and which chunk it should cite are both designed when the
   corpus is written (see the `gold_chunk_ids` validation in the golden set);
3. **Easy to explain** — in a demo you can state plainly that the corpus is self-written, so answer
   quality is not confounded by third-party content or style.

The binary samples (`.txt` / `.docx` / `.pdf`) are generated by
[`tools/build_sample_binaries.py`](../tools/build_sample_binaries.py) — edit the script and re-run
it rather than editing the binaries by hand. Note that the `.txt` is intentionally **GBK** encoded
to exercise the loader's encoding detection; do not re-save it as UTF-8.

All corpus content is written by the project author (see the repository LICENSE) and may be freely
used for demos and redistribution.
